# GalReverse

围绕用户遇到的具体障碍，还原从资源存储到游戏消费的必要路径，交付有证据的格式说明、分析结果或可复现的最小修改。先确认目标版本，再通过观察、假设、实验和对照逐步减少不确定性。

## 输入与工具

从请求和项目中确定游戏目录、平台、版本或补丁、目标资源、当前症状、期望输出以及是否需要实际修改。已有信息足够时直接开始；只询问会影响分析路线的缺项。先记录可执行文件及代表性资源的大小与 SHA-256，保留原件，在独立工作目录保存实验与产物。

本技能提供方法与参考资料，不随附调试器、游戏解析器、密钥、编译器或 Hook 运行文件。先发现环境中已有的工具，再选用：十六进制查看器和 Python 适合初筛；IDA/Ghidra 适合静态分析；x64dbg/WinDbg、Frida 或目标平台调试器适合动态观察。工具不是固定依赖，不能假称存在某个宿主 API。使用具体工具前确认本机版本及命令帮助，安装和下载遵循用户已有授权。

若已安装 GalExtract 或 GalPack，可复用其已验证工具及流程；没有安装时，按当前可用工具完成本任务，不依赖兄弟目录存在。

## 选择分析路线

| 当前障碍 | 优先读取 | 要解决的问题 |
| --- | --- | --- |
| 归档无法提取、条目仍不可读、文件名只有哈希 | [资源结构与算法](guides/formats-and-algorithms.md) | 索引、变换层级、解码函数或名称解析规则 |
| 能提取但不能导入超长对白 | [资源结构与算法](guides/formats-and-algorithms.md) | 脚本长度、偏移、跳转和资源引用 |
| 乱码、缺字、文件路径异常、自定义字库 | [编码与字体](guides/text-and-fonts.md) | 字节解释、字符遍历、字形映射及渲染 |
| 封包困难、需要免封包或动态替换 | [加载与运行时替换](guides/runtime-replacement.md) | 加载优先级、替换层级、缓冲区所有权 |
| 可执行文件中的长文本、ARM/ARM64、Unity IL2CPP | [原生程序与 IL2CPP](guides/native-and-il2cpp.md) | 地址映射、代码引用、语言状态及平台封装 |

按本次问题读取对应资料，跨层失败时再补读相关路线。原文索引、抽象来源与历史示例的适用边界见 [来源与抽象](provenance/sources.md)。

## 公共工作流程

### 1. 建立可比较的基线

- 复现用户指定的症状，选一个有代表性的条目、场景或脚本，记录触发步骤及预期行为。无法运行游戏时，先进行文件分析并标明运行验证不可用。
- 检查文件头、相邻资源、索引与资源文件的对应关系。区分容器、压缩、加密或混淆、脚本结构、字符编码和渲染问题；不可读文本或高熵只能支持猜测。
- 查询目标引擎及版本的现有解析器和源码；能直接解决时复用。可读不代表可写，提取出的数据也可能已经过额外解压或转换。

### 2. 定位数据经过的关键边界

先画出本任务需要的一段数据流，例如：文件或归档条目 → 读取缓冲区 → 解密/解压 → 脚本对象 → 文本/图像/音频消费者。给每一层标明输入、输出、长度单位和资源身份。

有动态环境时，从文件访问、已知文本或资源消费者切入，用条件日志、调用栈和缓冲区访问断点连接上下游；缓冲区重分配后重新定位。只能静态分析时，从文件 magic、特征常量、错误字符串、交叉引用、RTTI 或虚表缩小范围。两种路线互补，不必从入口逐函数通读整个程序。

记录模块身份、文件偏移、RVA/VA 的类型及换算依据。堆地址只属于当前运行；反编译器自动生成的类型、函数名和参数只是线索。关键结论须回看汇编或用输入输出对照验证。

### 3. 选择并证明最小方案

依据目标选择离线解析与重建、引擎原生目录加载、解码后整文件替换、文本级替换或可执行文件修补。先用一个可识别的改动验证选定路径，再扩展至目标资源集。

为每个假设记录能证伪它的检查。例如“目录文件优先”需要观察实际读取结果；“某函数是解压器”需要确认输入和输出；“语言 getter 控制全部文本”需要检查初始化和其他访问路径。不要把文章中的偏移、寄存器、格式参数或版本结论复制为当前游戏的事实。

### 4. 实现、验证并收尾

解析器或算法先保持与目标行为一致，再整理命名与结构。写入器和补丁应在输入版本、原始字节或结构不匹配时明确失败；默认输出到新文件。修改资源时更新实际受影响的长度、偏移、索引、引用和校验，不以跳过所有检查代替理解格式。

按 [证据、验证与交接](guides/validation-and-handoff.md) 保存复现资料并验证结果。首次验证一个代表性样本，再覆盖本次目标及会受影响的边界；输入、实现和配套映射未变化时复用已有结果。发现新失败才扩大检查范围。

缺少密钥、目标版本、调试环境或加载器支持时，准确列出缺项、现有证据和下一步可执行实验，交付当前有效结果；不能把环境受限表述成格式不可分析，也不能把局部成功表述成全游戏完成。

## 与资源工作流交接

GalReverse 负责解除未知格式与加载逻辑的障碍。脚本、图像、音频等资源的常规解包可交给 GalExtract，需要时另行解析对白与语音关联；语音生成可交给 GalTTS；已确认格式的资源封包与归档重建可交给 GalPack。仅在用户任务需要时衔接这些阶段。

交接至少包含目标版本与哈希、资源身份和相对路径、每层数据状态、已验证的格式或加载规则、工具及参数、产物绝对路径、验证结果与未解决项。动态 dump 不一定是原样归档条目，不能直接作为重建基线；名称哈希尚未恢复时保留条目 ID 和已确认映射，不能杜撰文件名。

面向资源修改与归档重建时，单独保留原样资源根目录和资源相对路径；解码后的工作资源及其到原条目的映射另存。需要 TTS 时，使 `audio_paths`、`asset_root` 和清单中的资源路径指向同一基准。按实际资源类型独立验证脚本结构与引用、图像布局或音频解码等边界，以及游戏读取行为。

## 引擎经验闭环

识别引擎后，按[经验积累流程](guides/engine-learning.md)查询用户本地库和[随包经验索引](catalog/experiences.json)，核对版本、方言和失效条件。每完成一次本阶段的真实验证，自动保存成功报告；有可分发的通用方法时收录为引擎资料。合成验证只能记录为合成等级，失败或未知结果不能写成成功经验。经验不改变任务范围与授权，用户指定仅本地保存时不修改技能资料。
