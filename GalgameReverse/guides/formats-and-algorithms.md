# 资源结构与算法

适用：未知归档、二进制脚本、解码失败、超长文本回填、哈希文件名。方法来源见 [R1、R4、R8、D2](../provenance/sources.md)，具体格式结论以目标输入为准。

## 从资源结构提出可验证的假设

先列出文件头、大小、重复区域、字符串和可能的配套索引。对候选字段记录偏移、位宽、端序、单位、相对基准和支撑样本；用多个条目检查数量、范围及对齐是否成立。索引与数据分离时同时读取两者，不把填充长度误认为有效资源长度。

将处理层分开标记：归档索引 → 条目原始字节 → 去封装 → 解密/解压 → 内部资源。无法读出文字并不能区分压缩、加密和二进制结构。常见文件头、窗口复制、码树、常量表只能提供候选方向，不能单独证明算法。

现有解析器只能列出文件名时，检查它停止在哪一层以及是否有未实现分支；不要重新逆向已经确认的结构。读取器支持某格式也不代表存在写入器。

## 从运行观察或代码定位生产者

1. 选择一个可确认身份的资源。动态可用时跟踪文件打开、定位和读取，记录路径、文件位置、请求/实际字节数、目标缓冲区与调用点。
2. 在读取完成后的有效数据范围观察后续访问或写入，找到产生目标结构的函数。重启或重新载入后通过稳定调用点找新缓冲区，不能复用上一次的堆地址。
3. 无法动态运行时，从 magic、分发标记和错误处理查交叉引用，结合现有源码理解数据流。虚调用需确认实际对象与虚表，不能按函数指针表达式猜唯一实现。
4. 先确认函数输入、输出、长度、状态与调用方如何使用结果，再决定是否需要完整还原内部算法。

## 还原算法并验证

先制作贴近原行为的实现，保留整数位宽、溢出、符号扩展、端序、指针步长和状态初始化语义。静态表要根据实际使用范围提取，零元素不一定是表结束；反编译器遗漏的分支或类型须对照汇编。

在原始输入和已知运行输出上逐字节比较。出现差异时定位第一个分歧，检查状态、索引和长度，不以“看起来像文字”验收。随后才合并变量、替换标准库实现或优化流程。补上与目标变换相关的截断、环形边界、重叠复制或尾块检查，防止坏输入越界或无限分配。

重新生成资源时，优先使用已确认的编码器；原样模式或 literal-only 只能在目标读取器确实支持时使用，并重新核对大小、标志及对齐。解压算法通常不能简单倒序变成压缩器。

## 脚本超长与重新导入

以指令或记录为单位解析，区分 opcode、操作数、文本、控制码和资源引用。确定长度单位、是否包含终止符，以及跳转/指针相对于文件、代码区还是下一条指令。

为旧记录位置到新记录位置建立映射，按实际引用类型回填长度、偏移、分支表和必要校验。未知指令保留原始字节；无法确定指令边界时先补证据，不扫描可打印文本后直接拼接整个文件。对白、人名、语音调用和控制标记的关联必须保留。

用短于、等于及长于原容量的文本覆盖本次写入边界；重解析新文件，检查所有受影响的引用落在有效记录上，未修改的逻辑和资源标识保持一致。

## 仅存哈希的资源命名

名称解析和内容解密分开处理。先观察脚本路径如何经过规范化、目录拆分和名称哈希变成归档查找键，再确定运行时函数的输入输出及状态。

采集多个“输入名称 → 运行结果”样本，涵盖目标实际使用的大小写、分隔符、非 ASCII 字符和目录层级。离线实现明确编码、终止符、密钥/seed、输出长度及端序；算法常量只用于提出候选，须用样本证明。

候选名称来自脚本、资源表或运行日志，通过计算匹配恢复关系；不能把这个过程称为逆转哈希。目录与文件可能使用不同函数或参数。记录碰撞、未命中、运行覆盖范围和未知 ID，不能仅凭一次吻合声称恢复全部名称。R8 的算法识别结果只适用于其分析样本，不固定为所有 hxv4 版本的规则。
