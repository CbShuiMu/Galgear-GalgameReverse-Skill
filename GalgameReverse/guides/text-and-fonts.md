# 编码与字体

适用：乱码、半角碎字、缺字、文件名转换失败、自定义图集和字库。方法来源见 [R2、R3、R6、R7](../provenance/sources.md)。

## 分别检查字节、字符和字形

| 现象 | 需要区分的原因 | 观察位置 |
| --- | --- | --- |
| 路径打不开 | 文件实际编码、路径规范化、A/W API 转换 | 文件访问参数及转换前后缓冲区 |
| 同一汉字变成两个字符 | 引擎按旧编码遍历新文本 | 首/尾字节判断、字符类型表、步进长度 |
| 字符内容正确但方框或错字 | 字体缺字、码表错误、字形选择错误 | 字符码到 glyph ID/图集位置的转换 |
| 正文正常、历史或菜单异常 | 不同消费者使用不同转换/字体路径 | 各场景实际调用链 |

读取同一段文本在文件、解码后、脚本对象和渲染入口的字节与长度，定位首次出现差异的一层。可成功解码不代表采用了正确编码；用已知文本、边界和引擎行为确认。

## 系统字体与字符转换

区分 CP932 与严格的 Shift-JIS、CP936/GBK 与 GB2312 子集，按目标转换器验证实际可表示字符。UTF-16 的单个代码单元不是所有字符的完整表示；长度记录明确使用字节、代码单元还是其他计数。代码页及 API 细节以 [Microsoft 文档](../provenance/sources.md) 为依据。

使用 `MultiByteToWideChar` / `WideCharToMultiByte` 等接口时，确认输入编码、输出容量和终止符语义，检查失败返回值。对目标内容验证转换是否丢字或使用了替代字符；不要对整个进程无差别地把所有日语转换改成中文转换，资源路径可能仍需要原编码。

字体侧沿实际调用检查 `CreateFontIndirectA/W`、字体枚举、`GetGlyphOutlineA/W` 或绘制入口。`lfCharSet` 影响字体选择，不承担文本转码。依据 SDK 的 `LOGFONT` 定义修改字段，不把代码页编号、字符集标识和某个结构偏移混用。

字节范围检测可能由比较、查表或优化后的算式实现。用目标编码的有效字符和非法/截断序列测试完整解析路径；不能把“最高位为 1 就占两字节”作为通用修复。同步检查正文、历史、选项、姓名和菜单的受影响消费者。

## 自定义字库与图片

先分开恢复三类信息：字符码到字形的映射、字形位置与度量、像素的存储布局。常见待验证项包括端序、偏移、尺寸与对齐、位深、palette/alpha、通道次序和 tile/swizzle。文件大小与图像观感仅能协助提出假设。

复杂位运算难以直接解释时，生成“存储索引 → 坐标/通道”的表或标记图，检查有效区域是否存在越界、重复覆盖或遗漏。明确填充区域后先做不修改内容的解码/编码往返，再替换少数字形。不能假设所有图集转换都是交换源与目标即可。

码位重映射应保留编码值、显示字形和引擎字符分类之间的对应关系，避免覆盖控制码、资源标识或其他共用字符串。扩大字库、重排码表和修改字符解析器是不同方案，依据受影响范围选择。

验收有效像素及原有填充规则、首尾字形、标点与中日混排，以及实际画面的字宽、基线、换行和裁切。图片替换另核对行步长、通道顺序、alpha 和上下方向；不能仅凭 PNG 文件能打开就认为引擎缓冲区兼容。
