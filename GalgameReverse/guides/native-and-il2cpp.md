# 原生程序与 IL2CPP

适用：PE 或 ARM/ARM64 可执行文件、ELF 中的长字符串、主机平台封装及 Unity 语言逻辑。方法来源见 [R4、R5、RS1](../provenance/sources.md)，加载和 ABI 规则另见同页第一方资料。

## 平台与地址先于补丁

确认指令集、位数、端序、文件格式、目标构建及加载方式。文件偏移、分析器显示地址、RVA 和运行 VA 分开记录。PE 使用实际节表和模块基址换算；ELF 使用对应加载段，文件范围内的映射依据 `p_offset`、`p_vaddr` 和实际加载偏移，不能把内存零填充区当成已有文件字节。

PSV/Switch 等平台的外层容器、压缩或元数据可能使分析器地址无法直接定位原文件。需要转换时记录原文件和中间格式的关系，转换后重新确认映射；不能在压缩容器中盲搜一段指令就覆盖。游戏版本、可执行构建和 metadata 必须对应。

只需资源解析时不必修改原生程序。只有目标确实涉及可执行文件内的逻辑或文本时，才走补丁路线。

## 可执行文件中的长字符串

先找到字符串及所有受影响引用，核对编码、终止符、容量和使用者是否假设固定长度。若容纳不了，选择目标加载器可映射的区域存放新数据，再更新引用；只给 ELF 添加 section 名称并不保证它会被装载。

修改布局后重新读取实际分配的地址和偏移，确认加载段大小、权限、对齐及相邻区域不冲突，保留必要的重定位。PE 增加节或 ELF 改段是不同格式操作，不能套用同一文件偏移公式。

ARM/AArch64 引用可能通过字面量池、PC 相对寻址、`ADRP` 配合 `ADD/LDR` 或重定位表构造。先识别完整序列，再计算新地址；修改共享字面量前检查其他引用。Thumb 存在不同宽度的指令，PC 及对齐语义依指令而定，不硬套“固定长度加常数”的经验。

汇编时使用正确的地址、架构和模式；生成后反汇编并重新计算目标地址，检查可达范围、寄存器活跃性和指令边界。不从文章截取一条“设置返回值”的伪指令当作通用机器码。ABI 也不能在 Windows x64、ARM32 和 AArch64 间照搬。

输出补丁记录源哈希、文件偏移、原始与替换字节、定位依据及修改原因。目标字节不匹配、匹配不唯一或地址换算不成立时明确失败。重新封装后检查格式及目标运行；普通 ARM Linux 样例可运行不能证明主机加载器接受最终文件。

## Unity IL2CPP 与语言状态

先区分序列化资源、脚本后端和原生模块。文本可能由资源 ID 或数据库索引加载，脚本旁的可读注释未必被使用；验证实际消费者，不能直接替换看到的第一份日文。

对 IL2CPP，配对同一构建的原生模块与 `global-metadata.dat`，确认分析工具支持该元数据版本。生成的类型声明、名称和方法地址用于导航，不能当成包含原始方法逻辑的 C# 程序。metadata 缺失或受变换时先记录证据及工具失败原因，不捏造可导出的类或偏移。

从 language/locale 相关类型、枚举、字段及引用定位状态，追踪初始化、setter、getter 和直接字段读取；同时检查保存设置、平台语言及缓存。某个 getter 返回中文不代表其他路径读取同一值。

若资源内已有目标语言，先检验资源完整性与实际语言选择机制，再决定是否需要代码修改。用同一版本中的枚举和行为确定目标值，不假设中文始终等于某个数字。修改后覆盖受影响的 UI、正文、选项、重启和存读档场景；资源里有译文不等于全游戏已完成汉化。

## 环境受限时

无法执行目标平台时，交付格式、地址映射、引用和补丁前置条件的静态结果，给出目标运行所需步骤及环境缺项。工具转换成功、反编译器显示正常或一段代码可汇编，都不能替代目标平台验证。
