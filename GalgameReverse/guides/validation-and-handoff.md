# 证据、验证与交接

## 保存可复现的分析事实

在用户工作目录保存分析记录，格式沿用项目习惯即可，不要求额外数据库。至少让下一位执行者能够回答：

| 记录 | 必需内容 |
| --- | --- |
| 目标 | 平台、游戏版本、补丁状态，可执行模块与关键资源的大小和 SHA-256 |
| 复现 | 场景、操作步骤、输入条目、预期行为和实际症状 |
| 定位 | 模块身份，文件偏移/RVA/VA 的类别，换算依据或本次运行的模块基址 |
| 数据 | 原始资源身份、处理层级、输入输出长度及单位、编码、相关缓冲区所有权 |
| 结论 | 已观察事实、仍待验证的假设、适用的版本/资源范围、证据文件或日志位置 |
| 操作 | 工具与版本、命令或脚本、修改前后字节或字段、产物哈希与回退方式 |
| 结果 | 已执行检查、通过/失败/未执行及原因、剩余条目和下一步实验 |

只记录可验证的观察和决定，不保存私有推理过程。密钥、用户路径和游戏内容留在本地项目中，不写入分发的技能。

## 根据实际修改选择验收

| 修改对象 | 有意义的检查 | 仍不能由此证明 |
| --- | --- | --- |
| 归档/结构解析器 | 条目范围、索引一致性、截断输入、输出数量及已知资源对照 | 引擎支持封包或补丁加载 |
| 解码/哈希实现 | 多个目标输入与运行时输出一致，覆盖相关边界 | 同名引擎其他版本也使用相同参数 |
| 脚本重建 | 重解析、长度和跳转目标、未修改指令及资源引用、超长样本 | 所有剧情分支都已运行 |
| 字库/图像变换 | 布局往返、有效像素、码表、边界字形和实际渲染 | 全部菜单或动态字体路径都已覆盖 |
| Hook/缓冲区替换 | 实际命中资源、容量和生命周期、重复载入、存读档/历史记录 | 未触发场景也没有其他消费路径 |
| 原生补丁 | 版本及原始字节匹配、反汇编、地址映射、封装后检查、目标运行 | 其他架构或平台环境也兼容 |

先验证代表性输入和本次修改特有的边界，再验证目标批次。运行时只加载过部分资源时记录已触发集合，不将运行 dump 宣称为全量提取。没有运行环境时交付静态检查及待运行步骤，不能把计划写成测试结果。

## 回退与交付

保留原始输入，输出使用新文件。补丁应用器应绑定源哈希或足够严格的版本及原始字节条件，拒绝错误版本和已修改目标。回退保留原件即可；确需反向补丁时同样验证其输入身份。

交付绝对产物路径、最小复现步骤、已确认的数据流与字段、适用版本、验证范围和限制。只做分析的请求交付结论和证据即可，不强制制作 Hook、安装包或补丁。

## 衔接 GalExtract / GalTTS / GalPack

- **提取阶段：** 提供原始归档、条目身份、格式/算法参数和已验证解析器。若提供对白与语音关联，保留脚本引用证据，不靠文件排序猜测关联。
- **TTS 阶段：** 提供确认的对白、说话人及音频路径；`audio_files` 与 `audio_paths` 等长并按索引对应。无确认音频的条目单独报告。`audio_paths` 相对于对应原样资源根目录，该目录作为 `asset_root`。
- **重建阶段：** 提供原样基线、修改资源、各层封装关系、索引/顺序/对齐要求及创建参数。运行时 dump 或解码 WAV 不冒充原样条目。文件名哈希未恢复时用稳定条目身份交接。
- **引擎验证：** 音频解码长度、缓冲区边界及最终资源的读取/播放结果单独记录；哈希或格式审计通过不能替代这些检查。

不假设其他技能已安装，也不承诺其后端支持新分析出的格式。必要时交付独立命令、格式说明及人工验证结果。
