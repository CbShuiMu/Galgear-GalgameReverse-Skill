## 格式特征与编码方式

- 本页只覆盖读取实现中的 release SPT：先对成员字节做逐字节 XOR `FF`，再核对解码后首项的 Data 标识 `0x66660001` 和 DataHeader `0x55550001`。不能对未知扩展名盲用 XOR。
- 数据按小端 32 位字排列。指令首字段是以字为单位的项长度，下一项索引为当前索引加该长度。地址表中的字索引乘四才能成为解码文件字节偏移。必须完整遍历并检查每项边界。
- header 的字索引 4–7 分别给消息数、消息表、字符串数和字符串表；Print/LPrint/Append 指令通过消息表项找到字符串，Select 指令使用字符串表。输出保留指令偏移、字符串偏移、原生消息编号和操作码；Draw 及其他消费者未实现，不能声称穷尽所有显示文本。
- XOR 是存储混淆，文本字符编码另行指定。读取实现使用 Shift-JIS；补丁可能采用不同编码，不能把某个项目编码写成引擎默认。严格解码失败应保留原字节并报错，不通过替换字符伪装成功。
- `姓名 + CRLF + 括号包围的消息` 由读取实现识别为姓名与消息；不符合的文本保留为无明确姓名，不能沿用上一条姓名。选项保留其原指令位置，不追加到整份正文末尾。

## 验证与失效条件

真实样本验证覆盖同一 release 布局的多个脚本及独立编码参数；未验证其他发行版本、dev SPT、所有控制操作码、跨场景可达性、完整剧情、语音关联或存档恢复。静态指令位置不是可直接加载的存档状态。解析器只读取与导出，不执行 SPT。

## 控制与旧存档版本边界

可对照 [SystemNNN 公开读取实现](https://github.com/tinyan/SystemNNN/blob/78a05053c78b3b80065a9a209c6685a7c60a2e83/nnnLib/execscript.cpp)核对字单位的 GOTO、SUB、调用表和脚本名表，保存目标指令边界。条件跳过还依赖块结构与表达式求值，不能只把物理下一条当作全部分支。

公开 `GAMESTATUS` 结构与部分旧发行存档的尺寸不同。只允许在匹配版本与结构证据下解释活动 PC；相同签名、相似头部和看似合理的整数不足以复用新版本固定偏移。项目参数和候选字段留在本地，不提升成全版本兼容性。

## CG 与差分图像（实测子集）

DWQ 与 override PNG 等不同来源分别保留。先按文件头识别，配套层和补丁不扁平合并，不以名称相似删除差分。 实际样本阶段见 [CG 状态表](../catalog/cg-status.md)，命令与边界见 [图像 CLI](../commands/garbro-images.md)。本节不声明完整 CG 或全部差分组合。
