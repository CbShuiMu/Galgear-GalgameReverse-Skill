# WillPlus / AdvHD：翻译表与说话人

本页提供格式与关联线索，不随附 WS2/LNG 通用解析器。先核对引擎版本、原始脚本、姓名本地化表和翻译归档；具体文件名、配置字节及消息 ID 语义须用当前文件验证。

## 读取原生消息与姓名

[DisplayMessage 实现](https://github.com/DarthFly/advhd_ws2_tools/blob/master/Ws2/Opcodes/DisplayMessage.php)将操作码 `0x14` 后的 DWORD 作为消息 ID，再读取 layer 和 message 字符串；较新版本另读配置字节。[SetDisplayName 实现](https://github.com/DarthFly/advhd_ws2_tools/blob/master/Ws2/Opcodes/SetDisplayName.php)用 `0x15` 读取显示姓名字符串，较新版本也可能有配置字节。

本地解析程序应在已确认的指令边界维护姓名状态，空姓名重置为旁白。不要仅搜索单字节操作码，参数和正文中也可能出现相同字节。

翻译表可能只含文本。检查同版本的 `.lng`、`.ws2`、人物表和配置；如有 `NameTable.txt` 一类资源，确认实际编码与分隔符。它可能是 UTF-16LE 的源姓名/本地化姓名对照，不能将控制前缀算入显示名或据此猜测真实身份。

## 本地程序的关联步骤

1. 读取并保存姓名表的源标记、本地化显示名、文件哈希和字节跨度。
2. 完整解析原始脚本，按原生消息 ID 保存当前姓名状态、消息指令位置、语音引用及关联表项。保留未显示或空的表项编号。
3. 只有证明翻译表的完整编号与原生消息 ID 对应后，才将翻译对白连接到原始消息。不能将过滤后的行号、文本偏移或候选命中序号当作消息 ID。
4. 按[对白映射与证据契约](../contracts/dialogue-audio.md)导出 `dialogue_id`、`speaker`、`source` 和实际语音路径；相关消息 ID 操作数、姓名引用和语音引用分别保存跨度。
5. 用一个代表性脚本核对姓名切换、旁白及语音，再批量提取；缺少个别姓名时保留未知并报告，不放弃其余已确认映射。

## LNG 变体检查

部分文件可能采用原生计数、独立长度数组和编码文本池。先从计数位置、长度宽度、终止符与池起点证明完整布局。若正文经过 XOR，保留原始文件及解码工作副本，并记录实际密钥和变换范围；计数和长度是否变换须分别核验。

完整走表后再筛选对白，空条目仍占编号。长度可能包括双字节终止符，须用当前样本逐项验证。不能把某个文件的偏移、编码或密钥推广到所有 LNG。

无需宿主专用映射 API。随包校验器只检查来源字节完整性和资源映射结构；消息 ID、表项与姓名状态之间的语义联系由当前本地解析器和对照结果证明。
