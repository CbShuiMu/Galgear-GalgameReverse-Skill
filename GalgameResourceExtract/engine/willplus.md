## 格式特征与编码方式

| 格式或层级 | 通用识别特征 | 编码方式与判定依据 |
| --- | --- | --- |
| `ARC/Will` 归档 | 按索引计数、名称字段宽度、偏移与大小识别，`.arc` 扩展名不足以确定布局 | 所引实现的文件名使用 CP932；只描述目录名称，不证明内部脚本文字也用 CP932。SCR/WSC 成员有按字节循环移位的还原分支；见[实现][arc-will] |
| `ARC/WillV2` 归档 | 与旧布局分别验证，索引名称为 NUL 结尾宽字符串 | 所引实现的文件名使用 UTF-16LE。WS2/JSON 成员有移位变换及条件分支，属于字节变换而非字符编码；见[实现][arc-v2] |
| WS2 脚本 | 编译后的二进制指令流；消息、姓名及配置字段的读取依赖版本 | 本页不指定统一字符编码；按同版本[字符串读取实现][ws2-reader]、长度/终止符和指令边界确认，归档文件名编码不能替代正文编码证据 |
| LNG 翻译表与姓名本地化表 | 先确认生成工具或加载器、表项编号、记录边界和原脚本引用 | 未确认通用编码与布局；结合 BOM（若有）、同版本读取实现及完整走表验证，不把单款游戏的 UTF-16、XOR 或固定偏移写成引擎默认规则 |
| 图像、音频及其他成员 | 提取后按各成员文件头和实际引用识别 | 媒体编码与归档、脚本文字分别确认，不因共用 `.arc` 就假定编码一致 |

适用版本与验证等级：本页依据所引 GARbro 与 WS2 工具实现提供方法参考，未声明真实样本或游戏运行验证。先核对当前引擎、索引和指令版本；布局、读取分支或引用关系不符时停止套用。特殊编码、变换参数及补丁行为留在项目本地记录。

## 注意事项

### 归档存储字节与脚本工作副本

GARbro 的相应读取器可能在提取时还原脚本字节，写入器再做反向变换；具体触发条件须核对所选格式实现。分别标记归档存储层与解码后的成员，保留原始归档，不对已经还原的脚本重复变换。先用代表性成员验证创建、重新提取和比对，再处理目标范围。

以下姓名和语音关联步骤仅在用户需要相应内容时执行。只需解包脚本或其他资源时，完成解包与条目核对即可；纯文本导出保留目标范围内的无语音记录，不要求生成对白映射。

### 读取原生消息与姓名

[DisplayMessage 实现][message]将操作码 `0x14` 后的 DWORD 作为消息 ID，再读取 layer 和 message 字符串；较新版本另读配置字节。[SetDisplayName 实现][name]用 `0x15` 读取显示姓名字符串，较新版本也可能有配置字节。

本地解析程序应在已确认的指令边界维护姓名状态，空姓名重置为旁白。不要仅搜索单字节操作码，参数和正文中也可能出现相同字节。

翻译表可能只含文本。检查同版本的 `.lng`、`.ws2`、人物表和配置；配套姓名表须独立确认字段、编码与分隔符，验证源标记和本地化显示名的对应关系。不能将控制前缀算入显示名或据此猜测真实身份。

### 本地程序的关联步骤

1. 读取并保存姓名表的源标记、本地化显示名、文件哈希和字节跨度。
2. 完整解析原始脚本，按原生消息 ID 保存当前姓名状态、消息指令位置、语音引用及关联表项。保留未显示或空的表项编号。
3. 只有证明翻译表的完整编号与原生消息 ID 对应后，才将翻译对白连接到原始消息。不能将过滤后的行号、文本偏移或候选命中序号当作消息 ID。
4. 按[对白映射与证据契约](../contracts/dialogue-audio.md)导出 `dialogue_id`、`speaker`、`source` 和实际语音路径；相关消息 ID 操作数、姓名引用和语音引用分别保存跨度。
5. 用一个代表性脚本核对姓名切换、旁白及语音，再批量提取；缺少个别姓名时保留未知并报告，不放弃其余已确认映射。

### 翻译表的识别与验证

从当前版本的读取实现确认表头、计数、记录长度、终止符和表项编号，再完整解析目标表；没有格式依据时先保留未知。字符解码、解压和解密分别证明输入输出与作用范围，项目使用的具体参数不写入本页。

完整走表后再筛选对白，保留原始空条目及编号；明确长度以字节还是字符代码单元计数、是否包括终止符，并核对表末边界与原始消息引用。不能将过滤后的行号当作消息 ID，也不能把某个文件的布局推广到所有 LNG。

无需宿主专用映射 API。随包校验器只检查来源字节完整性和资源映射结构；消息 ID、表项与姓名状态之间的语义联系由当前本地解析器和对照结果证明。
