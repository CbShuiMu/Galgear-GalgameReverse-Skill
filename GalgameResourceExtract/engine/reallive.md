# RealLive / AVG2000：SEEN.TXT 与场景成员

## 解包与封包工具

| 工具与来源 | 解包或读取用途 | 封包或回写用途 | 适用版本与限制 |
| --- | --- | --- | --- |
| [RLdev SEEN CLI](../commands/rldev-seen.md)，随附工具 | 按 10000 个场景编号拆出原样 `SEENnnnn.TXT` 成员，列出编号、偏移与大小 | 以原样成员重建 10000 槽索引；保留原场景编号 | 基于 [RLdev 归档实现][archiver]的保守适配，Python 标准库 CLI；不解压、解密或编译脚本，拒绝把 `KPRL` 等工作文件作为原样成员封包 |
| [GARbro CLI](../commands/garbro.md)，随附工具 | 识别并读取其支持的 RealLive/AVG 归档、图像及音频 | 当前随附可写列表没有 RealLive `SEEN.TXT` 写入器 | 可识别标签与当前实现为准；资源转换输出不能替代原样成员基线 |
| [RLdev：kprl / rlc][rldev]，外部工具 | `kprl` 包含原样归档拆分、脚本解压和反汇编等不同动作 | `kprl` 可处理归档重建与脚本压缩，`rlc` 编译脚本 | 上游针对 AVG2000 / RealLive；所引固定版本为 GPL-2.0-or-later，完整编译器与 OCaml 等依赖未随附。游戏附加变换和指令版本需要独立核验 |

工具路径相对于本技能根目录。`SEEN.TXT` 的归档拆分、成员内部解压与解密、指令反汇编、脚本编译是不同步骤，不能只凭输出扩展名判断已经完成哪一层。

## 格式特征与编码方式

| 格式或层级 | 通用识别特征 | 编码方式与判定依据 |
| --- | --- | --- |
| RealLive `SEEN.TXT` 归档 | 常见实现没有统一 ASCII magic；文件开头是 10000 个 `(offset, length)` 小端 32 位整数对，共 80000 字节，空槽长度为 0 | 索引使用数字场景编号，不含文件名字符编码。按全部条目的边界、重叠和成员头核验，不能只凭文件名 `.TXT` 判成文本；见[归档实现][archiver] |
| 场景成员 `SEENnnnn.TXT` | 成员头包含头部尺寸、编译器版本、数据偏移和尺寸；所引读取器区分 `0x1cc` / `0x1d0` 等布局，以及工具工作头 `KP2K` / `KPRL` / `RDRL` 等 | 先按头部布局确定字节码和压缩数据边界；同名 `SEEN` 成员与独立文本脚本不同。工作头是工具状态，不能自动视为游戏原始格式；见[头部读取实现][bytecode] |
| 脚本字符编码 | 文本位于字节码字符串或反汇编工作文件中，须先确认真实字符串边界与转义规则 | 所引 RLdev 支持 Shift_JIS / CP932、EUC-JP、UTF-8 的输入输出转换；其中 CLI/工作文件编码选择不证明游戏运行时字符串采用同一编码。以同版本指令读取器、系统配置及实际字符串往返确认，不能据汉化版或单款作品写成统一 UTF-8 / GBK；见[编码实现][encoding] |
| 压缩与加密层 | 标准压缩路径和 XOR 变换由成员头、编译器版本与读取实现决定 | LZ 系列压缩、公共 XOR 处理和项目附加 XOR 是字节变换，均与字符编码分开。上游也存在按游戏选择的额外变换；不将其密钥或覆盖区间推广为引擎通则；见[压缩实现][compression] |
| 图像、音频及视频 | 与 `SEEN.TXT` 脚本归档分别识别；按实际成员头确认 G00、NWA、OVK 等候选 | 媒体编码由各自资源格式和版本确定，`SEEN.TXT` 索引不能说明音频采样格式或图像压缩方式 |

适用版本与验证等级：来源为 RLdev 固定提交 `634b6c5ad1adfae3b94082993295fad75224a843`；随附 CLI 仅对严格检查的 10000 槽原样归档完成合成文件往返验证，没有真实游戏运行验证。归档边界、成员头或版本不符时停止套用；单款游戏的附加变换、字符替换表与密钥保存在本地。

## 注意事项

### 场景编号是条目身份

保留完整编号及空槽，不能把提取结果按文件名排序后重新连续编号。只有核对全部非空槽的编号、数量和字节哈希后，才能把原样成员目录交接为该归档的原样资源根目录。保存原始 `SEEN.TXT`，脚本解压、文本导出和反汇编工作产物另存。

### 工作文件与运行文件分开

RLdev 的原样拆分动作与解压动作不同：后者可能改写成员头并输出供工具继续处理的工作文件；`KPRL` 等标记不保证可直接交给原引擎。`kprl pack` 在所引代码中还是单成员压缩动作，归档重建走另外的路径，不能凭命令名称猜测操作层级。重建后用原样拆分重新比对所有场景，脚本改动再核对指令引用与编码。

### 对白与语音关联

需要对白与语音关联时，从实际场景指令、语音命令参数和配套语音索引建立关系；场景编号、文本物理顺序与音频文件枚举顺序不能互相替代。只需脚本或其他资源提取时，不强制执行对白解析。
