# Artemis：PF6 / PF8 归档

## 解包与封包工具

| 工具与来源 | 解包或读取用途 | 封包或回写用途 | 适用版本与限制 |
| --- | --- | --- | --- |
| [pfs-rs CLI](../commands/pfs-rs.md)，随附，上游 [pfs-rs / pf8][upstream] | 列表、提取以 `pf6` 或 `pf8` 开头的 PFS 归档 | 创建 PF8；目录和文件可以作为输入 | 随附版本为 `0.2.5`，读取 PF6/PF8 不等于可创建 PF6。当前写入名称为 UTF-8；旧版非 ASCII 文件名往返须特别核对。分包与路径规则见命令页 |
| [GARbro CLI](../commands/garbro.md)，随附，标签 `PFS` | 对所实现的 Artemis PFS 分支提供读取和提取候选路线 | 没有对应 PFS 归档写入器 | 以当前构建实际识别为准；不能把其他引擎同扩展名的 `.pfs` 当成 Artemis。需要精确能力时先看 `i` / `l` 结果与[读取实现][garbro] |
| [Artemis 官方工具与资料][official]，外部，未随附 | 核对脚本、宏及目标平台的资源使用规则 | 有对应工程时，沿用匹配版本的官方构建流程 | 官方说明的脚本语法不等于 PFS 二进制格式规范；当前技能没有通用 Artemis 脚本解析或编译器 |

## 格式特征与编码方式

| 格式或层级 | 通用特征 | 编码方式与判定依据 |
| --- | --- | --- |
| PF6 / PF8 归档 | 前三字节分别为小写 `pf6` 或 `pf8`；随后是小端索引大小、条目数及名称、偏移、大小等字段 | 按签名分流，检查索引边界与数量；不依赖 `.pfs` 扩展名。布局与版本依据见[格式实现][format] |
| 索引名称 | 每条名称有长度，索引还包含偏移和大小信息 | 所引 pf8 库先尝试 UTF-8，失败后尝试 Shift-JIS；这是工具的兼容读取策略，不是“全引擎固定 UTF-8”的证明。写入器使用 UTF-8 字节，因此旧名能解码也不证明按原编码写回；见[格式实现][format]和[写入器][writer] |
| PF8 成员字节处理 | 所引实现对索引数据计算 SHA-1，作为循环 XOR 的派生数据 | XOR 属于归档层混淆，与字符编码、压缩及媒体编码分开。所引实现按扩展名对 `mp4` / `flv` 走未加密分支；该规则只适用于匹配实现，不能自行扩展到所有视频或定制归档；见[读取器][reader]与[过滤规则][constants] |
| PF6 成员字节处理 | 所引读取器对 PF6 不启用 PF8 的 XOR 分支 | PF6 可读不代表用 PF8 创建器可原版重建；也不能从“没有这一层 XOR”推断内部脚本或媒体一定没有其他包装 |
| 归档成员压缩 | 当前 pf8 实现主要处理索引与 XOR，不提供通用成员解压 | 提取后继续检查各成员文件头；压缩脚本、媒体编码和其他内部封装分别处理，不对所有成员试同一解压算法 |
| 脚本及文本资源 | 官方脚本采用标签、参数及宏等结构，和 KAG 有语法渊源；实际发行资源可能包含不同层级的脚本 | 先区分明文、编译产物和中间格式，再依据同版本读取器、文本声明或严格解码确认字符编码。PFS 名称的 UTF-8/Shift-JIS 策略不能作为脚本正文编码证据 |
| 图像、音频、视频等成员 | 按文件头和脚本实际引用识别 | 媒体编码与 PFS 混淆独立；保留原媒体及标签，转换资源另存，不由引擎名推定统一格式 |

## 注意事项

PFS 归档层解除 XOR 后，所得成员可以作为归档内容层的原样资源根目录；它与原归档中被 XOR 的存储字节不同。始终保留原始归档，并记录实际层级。无需额外再对所有提取文件做 XOR。

多份 `root.pfs`、`.pfs.000` 等文件先分别列表；不能仅凭编号判断它们是一个文件的连续字节分卷，或认定同名条目的覆盖顺序。提取多个归档时用 `--separate` 保留来源，先保存各自清单，再按当前加载规则处理冲突。

创建时使用命令页中的尾部 `/` 与 `--no-smart-detect`，明确保留的是目录内容还是目录名。`system.ini` 智能检测可能影响路径；应对照原归档路径，不能以“文件都存在”替代条目路径一致检查。

PF8 重新封包会重建索引并重算派生数据，故归档字节通常不必与原包相同。应重新提取到独立目录，比较相对名称、数量与 SHA-256；旧 PF6、Shift-JIS 非 ASCII 名称或不同视频混淆规则存在兼容性缺口时，不声明完成原版往返。

官方语法相似不等于能直接套用 KAG 解析器。仅在需要对白记录时解析实际脚本；需要对白与语音关联时跟踪当前宏、变量和声音调用，不按文件序号配对。
