# CG、差分与原生图像提取

任务要求 CG 时，逐款建立图像专项记录，不沿用“脚本已提取”或“归档工具可用”作为图像完成证据。继续已有项目先检查身份并复用仍有效的原样资源；结果默认写入技能包之外的新目录。

## 选择范围与保留差分

- 从归档索引、散文件图像和脚本／图库引用定位候选。事件图像包和 `event`、`evcg`、`cg` 名称可帮助筛选，但只是候选分类；背景、立绘、缩略图与 UI 不计为已确认的独立 CG。
- 同一图像的表情、服装、局部覆盖、透明度、蒙版和子图均保留。不按感知相似、文件哈希或 basename 删除差分；同名资源位于不同归档、补丁或语言时保持独立来源。字节一致的备份可以复用已核验结果，但必须保留两处来源及哈希。
- 原始归档／散文件保持只读；原样资源根目录存工具返回的逻辑成员，并标记是否已做容器解压／解混淆。原始归档和成员层级分别记录。PNG 转换、副本拼接和清单另存，不能覆盖原生资源。
- G00 v2、HG 等容器可能有多个子图。用匹配的归档读取分支枚举全部非空子图，保存子图 ID、顺序、画布、原生偏移与解码尺寸。只导出一个默认合成图不能验收为全部差分。配套 RC8 等透明度数据与 RCT 基图一起保留，未经核验不自行合成最终 CG。

## 分阶段验收

| 阶段 | 需要的证据 | 不自动证明的内容 |
| --- | --- | --- |
| 候选定位 | 原始来源、完整相对路径、版本／签名、归档索引或脚本引用 | 是独立 CG、剧情覆盖完整 |
| 原生资源保留 | 每个来源独立目录、选中／导出／失败数量、大小和 SHA-256 | 图像能正确解码、全部差分可组合 |
| PNG 解码 | 明确对应的原生成员或子图、尺寸、透明度与偏移元数据、实际读回检查 | 游戏内布局、色彩与叠放关系已验证 |
| CG／差分完整性 | 实际加载包、补丁优先级、图库及脚本引用覆盖、全部子图／外部纹理和组合规则 | 其他版本兼容或封包成功 |

磁盘预算与单款时间预算写在本地任务中。超时、未知格式或单个资源失败时保留已完成文件和失败清单，明确剩余归档／成员／解码项；不能把目录存在或工具退出 0 当作全部完成。未变化的成功输入和产物不重复转换。

使用 [GARbro 图像批处理 CLI](../commands/garbro-images.md) 时，JSONL 清单区分 `raw`、`png`、`frame_container`、错误与延期。可用 `scripts/cg_inventory.py GAME_OUTPUT AUDIT.json --verify-hashes` 核对清单路径、大小、SHA-256 与 PNG 尺寸；统计只计算物理资源，不能生成“独立 CG 数”。

Unity 的 Texture2D、Sprite 和图集可能同时描述同一画面。保留对象 ID、原始序列化对象、外部流及完整源 bundle；导出 Texture2D/Sprite 不等于取得全部高层 CG 组合。标题专用 DAT、定制加密或格式参数留在本地，不推广为通用 Unity 支持。

本地状态表按“未尝试／读取受阻／原生保留／部分解码／所选范围通过”记录，并单列差分与语义完整性。随包引擎经验只保留已验证的方法、版本与限制；图片、游戏内容、存档、密钥和用户工作目录不进入技能包或远端。
