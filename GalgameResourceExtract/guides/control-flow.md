# 从消息消费者到分支图与存档坐标

需要补齐姓名、剧情分支或存档位置时，在已有提取结果上工作，保留先前版本及其证据。不要覆盖被经验报告引用的解析器、来源快照和产物；新实现与新结果写入独立目录，再记录新经验。

## 消息与姓名

1. 找到真正的显示消费者。字符串池中没有分类出的正文时，检查封装函数、外部数据库和本地化表，沿实际参数及行列 ID 建立引用。不能把“某个整数看起来像字符串编号”当作关联依据。
2. 姓名指令可能与正文分离。保留指令偏移及姓名来源，在控制流合流处做保守数据流分析；不同前驱带来不同姓名时保留歧义，跨未知调用不继续假定姓名状态。已消费的待定姓名不自动沿用给下一条旁白。
3. 数据库的显示姓名可能经过运行时昵称替换。保留原姓名字段、替换键及未求值状态；不要从作品知识补出身份。
4. 文本表可能另有选项集合。逐一检查具名 `select` 表、菜单体和消息消费者，不能只遍历数字键就宣称文本完整。不同语言、分包和备份分别计数。

## 分支图的证据类型

| 图中关系 | 必须保存的依据 | 验收边界 |
| --- | --- | --- |
| 局部字节码跳转 | 操作码、地址基准、长度单位、源偏移和目标指令边界 | 静态目标正确不证明该条件实际可达 |
| 子程序或跨场景调用 | 原生调用参数、场景身份及入口；字面量与动态表达式分开 | 返回栈和变量未还原时，继续点只能标为调用继续位置 |
| 源脚本菜单及条件体 | 源文件、行号、缩进/语法结构、原条件表达式和目标标签 | 不执行项目 Python、Lua 或任意表达式；未知语法保留未解决 |
| 数据引用 | 字符串/数据库操作数与目标资源位置 | 引用图不是可执行分支图 |
| 物理下一块 | 原始块序号及顺序 | 宏可能转移控制，不能冒充运行顺序 |

完整剧情验收要求覆盖实际加载资源、所有消费者、菜单与分支目标、动态跳转、调用/返回及补丁优先级。只有指令遍历或图端点检查通过时，只报告这些范围。大量静态节点也不能代替剧情完整性。

同一安装有多个归档时，先核对整个候选清单与索引；提取失败不能掩盖另一个尚未尝试的脚本包。按容器、版本、解包、脚本读取和消费者分类分别记结果。只保留可再分发许可明确的外部工具源码，固定提交与哈希；无许可的候选仅用于本地研究并记录未收录原因。

`scripts/parse_ast_flow.py ROOT OUTPUT.json` 可在不执行宏的前提下解析字面量 AST 场景与标签引用。它只在同一资源组中解析精确场景名，不把不同归档的同名文件合并，也不将引用唯一性当成宏执行顺序。

## 存档位置的四个等级

| 等级 | 可声明的内容 |
| --- | --- |
| 缓存或文本候选 | 存档含有某段文本、脚本名、语言键或 CRC；可能来自回溯与预加载 |
| 活动字段已解码 | 由匹配读取实现解析活动场景、行号、PC；与选择历史、全局数据分开 |
| 静态坐标一致 | 活动 PC 命中对应脚本的指令边界，行号及邻近文本一致；仍注明脚本版本身份 |
| 游戏内恢复已验证 | 同版本游戏实际加载，并验证所报告位置和相关状态 |

新旧存档结构尺寸不同、字段新增或槽位来源不一致时，不套用另一个版本的固定偏移。即使头部签名相同，也须保留版本与未确认项。解压失败不能直接当作存档加密证明。

Ren’Py 槽位也可能保存在配置指向的用户目录，不能只检查游戏目录。匹配旧式 `(roots, RollbackLog)` ZIP 存档时，可用 `scripts/locate_renpy_save.py SLOT.save RPYC_ROOT OUTPUT.json`：通过 `pickletools` 和惰性对象图读取活动 `log.current.context.current`，与 RPYC 原生节点身份比较；回滚历史单独计数。辅助读取器不导入 pickle 中的类、不执行 reducer 或游戏 Python。仅覆盖实际测试的旧格式和操作码，现代 RPYC2/存档布局遇到时保留未解决。

活动节点可能是下一条将执行的语句，保存的上一条显示文本不一定与之相同。报告两者的一致性，不能用回滚历史中的某个文本命中替代活动节点。存档头包含姓名而消息表将姓名与正文分列时，分别比较正文及明确的姓名拼接，并记录采用的比较规则；不任意删除字符来制造一致。

### 翻译表无法读取时的前情提要

优先用存档字幕在同语言的已解析记录中查找。翻译表暂时无法读取、存档同时含有可辨认的场景标识和字幕时，先按场景及资源版本缩小范围，再对照原版的实际对白。核对译意、姓名或邻近台词等可用线索，保留原始字幕、脚本记录位置和匹配理由。仅在场景内有一个可信候选时，才以该句为前情提要的截断点。存在多个候选或场景版本不明时，保留歧义。

这一方法已在带独立语言覆盖的 WillPlus 样本中与同语言表的唯一命中交叉核对。跨语言对照仍属于文本候选。保留原生消息编号与导出记录序号的区别，提要只使用锚点及以前的记录，活动游标和游戏内恢复另行验证。

## 提取器的分阶段失败

工具非零退出可能发生在附带源码恢复或后续转换阶段。检查已经产生的成员身份、数量、边界和独立解析结果后，分别记录成功阶段与失败阶段；不能把非零退出一律当作全部失败，也不能把部分成员存在当作整个命令成功。

实际项目的消费者编号、列号、编码、密钥、游戏内容和固定偏移留在本地；只将可复用的识别与验证方法写入引擎资料。
