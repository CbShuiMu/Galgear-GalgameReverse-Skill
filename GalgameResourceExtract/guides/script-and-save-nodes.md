# 脚本位置与存档节点的分别验收

需要提取台词和存档节点时，将以下产物分开保存，不能以一种数量替代另一种数量。

整理完整剧情、姓名与语言、跨场景流程时，同读[剧情转录与位置证据](story-export.md)。存档内命中的文本、语言引用或 CRC 可能属于回溯日志与缓存，未解析活动程序计数器前只能交付候选范围。

| 产物 | 必须保留的证据 | 不能直接推断的内容 |
| --- | --- | --- |
| 原样脚本或已解码场景 | 原始归档、成员路径、内容层级、大小、哈希与完整性范围 | 可读台词、实际运行顺序 |
| 台词记录 | 指令或原生字符串编号、来源位置、分类规则；未确认内容单列 | 字符串池全部都是对白 |
| 静态节点 | 场景身份、标签类型、入口编号、代码偏移或源脚本行；偏移相对基准 | 该节点可直接写入存档或恢复运行 |
| 存档样本清单 | 原路径、文件头、大小与格式识别；操作分析副本 | 配置、全局进度或缩略图都是槽位 |
| 存档恢复节点 | 同版本存档字段解析、场景与程序计数器对应关系、游戏内加载验证 | 静态标签可以独立恢复完整变量和调用栈 |

## 串行批量任务

每款游戏独立保存清单、命令 argv、退出码、超时、原始诊断、提取产物与未解决项，再进入下一款。给难例设置有限尝试预算，超时后标记跳过并保留下一步，不把跳过列为成功。重新尝试前复用已验证产物，避免覆盖。

先依据文件头、程序与读取器确认实际版本，不根据游戏名绑定引擎。移植版、汉化补丁和遗留存档可能属于不同运行时；资源包与存档须分别识别。多个补丁包保持独立来源，不按文件名排序擅自决定覆盖关系。

## 工具输出核对

人类可读列表不是稳定协议。把列值与至少两个实际成员的长度、连续边界及归档范围对照后，才能用于筛选大小或完整性统计。列标题与实际语义不符时保留原日志，并在本地适配器中记录证据；不要单凭列标题建立全局规则。名称解码异常、零长自引用占位条目或误识别出的其他格式不能作为解包成功依据。

只读分析工具也可能生成同名旁置文件。分析存档前复制到工作目录；尤其检查会写出全文转储的工具。静态节点 JSON 必须明确记录 `runtime_verified: false`，只有实际验证过加载行为才提升等级。

## 经验收录边界

按实际通过的阶段分别记录：归档解包成功可收录为提取经验，但不能把它描述为完整台词解析或存档恢复成功。统计分别列出脚本文件、已分类台词、候选文本、静态节点、存档样本和已验证恢复点。游戏路径、对白、密钥、固定偏移和原始日志留在本地。
