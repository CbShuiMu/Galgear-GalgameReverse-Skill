# 资源提取流程

## 确定目标与交付范围

在工作记录中写明目标资源类别、全部资源或子集的筛选条件，以及原样文件、可编辑资源或结构化内容的交付阶段。解包后按目标选择下文的解码、解析或对白与语音关联步骤；记录当前工具与版本的已验证能力，未确认的格式或版本不能视为已支持。

## 识别与解包

检查文件头、目录、配套表和版本证据；扩展名只用于缩小候选。按[工具索引](../commands/index.md)列出归档后，再读取需要的成员。保存条目完整路径、原始归档身份和 stored/decoded 层级，限制成员数量、大小和累计输出量；拒绝路径穿越、重名覆盖和越界。

不可读时依次区分容器、压缩、二进制脚本、字符编码及加密/混淆。先核对文件头、偏移与长度，再查询同引擎同版本的解析实现。简单 XOR 或移位也须由结构、边界和多条结果验证；复杂算法缺少密钥时准确记录缺项。不要仅因常见编码解码失败就宣告无法提取或立即改用 OCR。

每个待重建归档保留独立的原样资源根目录。不在其中写映射、报告或转换结果；额外解码结果另存并记录到原条目的对应关系。Mangetsu 条目名称、NAM、索引和扇区填充，或 CRI cue、wave ID 等，按对应工具文档分别核对。

按列表核对所选成员的完整路径、数量、提取状态及可用的大小或哈希信息。用户只需子集时交付明确的筛选范围；未核对全部条目的目录不能标为完整重建基线。未知条目保留原样并报告，不能因为当前工具不能解码就从资源结果中删除。

## 按需解码与解析

- **脚本与文本**：只需脚本文件时原样交付。需要可读或可编辑内容时，验证对应版本的指令、字符串表、编码和重建条件；文本导出保留请求范围内的无语音对白、界面文字或其他目标内容，不以能否生成对白映射筛选。
- **图像、动画、音频与视频**：先核对容器与资源本身的格式，只有目标需要且工具支持时才转换。记录尺寸、通道、时序、循环或轨道等当前格式相关属性；转换成功不能替代游戏兼容性验证。
- **字体、配置及其他数据**：保留原始名称、相对路径和字节；需要解析或修改时，先证明格式结构及引用关系，再对代表样本处理。没有对应实现时明确交付原样资源与缺少的解析能力。

解码或解析先核验代表性资源，再批量处理目标范围。转换副本保存来源与参数，便于后续封包恢复所需格式；不在仅要求解包的任务中自动修改或替换游戏资源。

## 可选：解析文本、姓名与语音关联

仅在用户需要对白与语音关联或计划交接 GalTTS 时执行本节及映射校验；单纯解包或文本提取无需满足对白映射契约。

1. 用一个代表性脚本确认指令边界、原生消息编号、控制码和字符编码。字符串池同时可能包含变量、标签和界面文本，不能将可读字符串列表当作剧情。
2. 同时读取消息及姓名状态。翻译表缺少姓名时，检查原始脚本、人物表和本地化姓名表，通过实际 ID、指令及消息编号关联，不能直接放弃已有的可验证关联。空姓名重置为旁白，`speaker` 记为 `null`；未知真实身份保留游戏实际显示的称呼，不用文件名或人物知识猜测。
3. 本地解析程序直接读取这些配套文件，保存输入哈希、表索引、指令位置及关联规则。证据检查使用随包脚本；具体字节布局见[引擎资料](../catalog/formats.json)。
4. 解析语音调用与对白的上下文关系。语音可能在同条记录中，也可能由前面的独立指令设置；先证明关联规则，再批量处理。
5. 优先按完整相对路径定位实际文件；只有 basename 或 ID 时，用已验证目录和命名规则消歧。缺少扩展名时查询真实候选；多候选未消歧、动态引用未还原或文件缺失时记录未解决项，不猜配。

清理显示控制码之前保留原字节、引用及消息坐标；空白项和共享字符串不能改变原生消息编号。同一音频的每次引用均保留，不把物理资源顺序当成阅读顺序。一条对白多个音频按调用顺序记录，进入 TTS 前明确与各音频对应的 `audio_segments`，不把整句重复交给每段；缺少分段依据时保留映射与未解决报告，标记尚未就绪。多人、分段语音或共享音频的格式与就绪条件按[映射契约](../contracts/dialogue-audio.md)。

## 校验与批量交付

资源提取按前述条目核对结果验收，解码或解析另核对目标格式的结构与代表性结果。输入、程序和相关配置未变时复用结果，分页查询沿用已有完整列表，不重复解包；仅因新失败或数据变化重验受影响阶段。

对白与语音关联路线的校验器 `scripts/validate_mapping.py` 使用标准库，检查显式资源路径、映射结构及 TTS 就绪状态；提供关联证据文件时另核对文件哈希、跨度和字节哈希。它不是通用资源校验器，也不验证消息操作码、调用关系或语义正确性，这些由解析器及代表性脚本对照完成。

需要关联时，先用当前版本的本地解析程序与代表性脚本对照，确认对白、姓名、语音调用、来源位置和关联规则，再批量解析目标脚本。批量结束核对已关联、无语音、缺失、歧义、失败数量；最终映射只收录已确认音频的对白，其他条目在报告或完整转录中保留。保存来源文件哈希和字节位置；映射变化后重新核对证据绑定。

交接时按实际执行阶段准备以下资料，产物路径使用绝对路径：

- **资源与基线**：实际引擎及版本证据、原始归档身份、格式标签、CLI 与完整命令、目标资源范围和筛选规则、原样资源根目录、资源清单、提取及未解决数量、校验结果和限制。
- **解码与解析结果**：记录与原条目的对应关系、所用参数及已确认创建参数；多层封装分别标记 stored、decoded 和工作资源。MRG 等格式额外交付 HED/NAM、条目顺序与填充信息。
- **对白与语音关联结果**：附映射、关联证据及已关联、无语音、缺失、歧义、失败统计；未完成分段或存在共享资源文本冲突时说明 TTS 尚未就绪。

重建辅助流程只验证提交的基线，不能自动证明它已包含原始归档全部资源；建快照前先核对提取完整性。
