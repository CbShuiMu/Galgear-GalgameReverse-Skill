# 提取与对白与语音关联流程

## 识别与解包

检查文件头、目录、配套表和版本证据；扩展名只用于缩小候选。按[工具索引](../commands/index.md)列出归档后，再读取需要的成员。保存条目完整路径、原包身份和 stored/decoded 层级，限制成员数量、大小和累计输出量；拒绝路径穿越、重名覆盖和越界。

不可读时依次区分容器、压缩、二进制脚本、字符编码及加密/混淆。先核对文件头、偏移与长度，再查询同引擎同版本的解析实现。简单 XOR 或移位也须由结构、边界和多条结果验证；复杂算法缺少密钥时准确记录缺项。不要仅因常见编码解码失败就宣告无法提取或立即改用 OCR。

每个待重建归档保留独立的原样资源根目录。不在其中写映射、报告或解码 WAV；额外解码结果另存并记录到原条目的对应关系。Mangetsu 条目名称、NAM、索引和扇区填充，或 CRI cue、wave ID 等，按对应工具文档分别核对。

## 解析文本、姓名与语音

1. 用一个代表性脚本确认指令边界、原生消息编号、控制码和字符编码。字符串池同时可能包含变量、标签和界面文本，不能将可读字符串列表当作剧情。
2. 同时读取消息及姓名状态。翻译表缺少姓名时，检查原始脚本、人物表和本地化姓名表，通过实际 ID、指令及消息编号关联；空姓名重置为旁白，不用文件名或人物知识猜测。
3. 本地解析程序直接读取这些配套文件，保存输入哈希、表索引、指令位置及关联规则。证据检查使用随包脚本；具体字节布局见[引擎资料](../catalog/formats.json)。
4. 解析语音调用与对白的上下文关系。语音可能在同条记录中，也可能由前面的独立指令设置；先证明关联规则，再批量处理。
5. 优先按完整相对路径定位实际文件；只有 basename 或 ID 时，用已验证目录和命名规则消歧。缺少扩展名时查询真实候选；多候选未消歧、动态引用未还原或文件缺失时记录未解决项，不猜配。

清理显示控制码之前保留原字节、引用及消息坐标。同一音频的每次引用均保留；一条对白多个音频按调用顺序记录。多人、分段语音或共享音频的处理按[映射契约](../contracts/dialogue-audio.md)，不把物理资源顺序当成阅读顺序。

## 校验与批量交付

校验器 `scripts/validate_mapping.py` 使用标准库，检查显式资源路径、映射结构及 TTS 就绪状态；提供关联证据文件时另核对文件哈希、跨度和字节哈希。它不验证消息操作码、调用关系或语义正确性，这些由解析器及代表性脚本对照完成。

先确认当前样本的对白、姓名、语音和来源，再批量解析目标脚本。批量结束核对已关联、无语音、缺失、歧义、失败数量；最终映射只收录已确认音频的对白，其他条目在报告或完整转录中保留。输入与程序未变时复用结果，分页查询沿用已有完整列表，不重复解包。

交接原包身份、格式标签、CLI 与完整命令、基线根目录、映射与证据路径及已确认创建参数。重建辅助流程只验证提交的基线，不能自动证明它已包含原包全部资源；建快照前先核对提取完整性。
