# 归档重建流程

先确定用户要修改的资源及范围、原始归档、原样资源根目录、替换资源、封包模式和新输出路径。脚本、图像、音频、视频和字体等资源使用同一归档重建路线，内部格式按资源类型验证。没有原始归档时，明确目标格式与创建参数，不能声称保留原始配置。默认保留输入；安装到游戏目录遵循用户已有授权。

## 确定兼容性要求

1. 使用所选工具检查原始归档及条目。GARbro 使用 `i`、`l`，并在创建前查询 `f --writable` 和 `options <Tag>`；Ethornell、pfs-rs 使用 `list`；Mangetsu 使用对应的 `mrg_info`、`mzp_info` 等命令，按索引核对资源；CriCodecs 使用 `INPUT -m --json` 和 `INPUT --list --raw --json`。
2. 使用实际检测到的完整格式标签，例如 `XP3` 或 `ARC/Will`，不要根据扩展名推断。原生 CLI 不使用 GARbro 的 `-t` 语法，应记录实际封装及对应命令。支持读取的格式不一定支持写入。
3. 从已有配置或证据中确定所需的归档版本、文件名编码、加密方案或密钥、压缩设置和目录结构。`i` 命令只识别格式标签，不能恢复全部创建参数。`options` 显示的默认值不能证明原始设置。
4. 检查当前写入器的限制。例如，XP3 和 NPA 的复杂加密方案无法通过此 CLI 赋值，NPK 需要有效的 AES 密钥，YPF 仅支持文档所述的旧版索引布局。如果无法表达必需的设置，报告具体限制，不要静默创建默认或未加密的替代归档。
5. 按资源类型检查原始文件与替换文件。脚本核对编码、指令、偏移、跳转和资源引用；图像核对尺寸、像素格式、透明通道及关联元数据；音频核对编码及容器、采样率、声道、循环等要求；其他资源按目标加载器的格式约束检查。保持文件名与相对路径不变。更改扩展名不是格式转换；仅在请求范围内执行必要转换，并保留源文件。
6. 涉及音频重新封装或影响解码缓冲区分配的长度字段时，执行[资源交接与重建](resource-workflow.md)中的“解码长度与越界预防”。按目标游戏解码器的口径测量并填写长度，区分压缩字节、采样帧和 PCM 字节。不能直接照抄 FFmpeg 的输出大小、旧语音长度或其他引擎的修复公式。其他资源的长度、偏移和校验字段按其格式规则验证。

## 准备资源集

根据用户意图选择模式。只有完整替换与补丁行为仍不明确且会影响兼容性时，才询问。

- **完整重建：** 将原始归档原样提取到新的暂存目录，再以修改后的资源替换对应资源路径。保留所有未被替换的原始条目。此次提取不要使用 `-ca` 或 `-if`，因为它们可能改变资源字节、名称或格式。
- **补丁归档：** 仅在已知游戏支持对应补丁机制时，只包含预期替换资源。根据证据确认所需归档名称和加载优先级；能够创建归档不代表游戏支持补丁。

按相对路径匹配替换资源，不要只按基本文件名匹配。报告未映射的替换文件以及缺失的预期替换文件。不要通过静默增加、遗漏或扁平化资源路径来消除不匹配。允许用户明确要求的新增或删除，并应反映在预期资源集中。

封包前记录预期路径和内容哈希。完整重建时区分未修改条目与替换条目。输出归档和验证目录应放在暂存目录之外。

普通资源修改由 AI 助手按上述规则准备暂存目录并记录预期资源清单，直接使用所选格式的封包工具，无需对白映射或 TTS 审计。`resource_workflow.py init` 可为各类原样资源建立基线快照。

接收 GalTTS 输出时，再用验证后的 `.galtts/resources.json` 执行 `resource_workflow.py merge`。GalTTS 的 `asset_root` 使用同一提取根目录。当前 `merge` 读取 TTS 专用交接字段，不能直接接收任意替换目录。它会检查源文件、映射和替换文件的哈希，即便 TTS 使用旧版扁平输出，也能恢复资源目录，并建立新的暂存目录。默认 `full` 模式保留全部未修改资源；只有确认游戏支持后才选择 `patch`。流程清单应保存在所有资源目录之外。每个原始归档使用一份基线清单。

## 创建归档

按所选工具的命令文档创建归档：

- **Ethornell：** DSC 需要重新压缩时，逐文件使用原始密钥；然后 `create INPUT_DIR OUTPUT.arc` 创建 ARC20。封装归档不会自动压缩 DSC，也不提供 BSE 加密。
- **Mangetsu：** 使用 `mrg_pack` 或 `mrg_replace`，保持原条目顺序、NAM 对应关系和扇区语义；`mrg_replace` 不复制 NAM。MZP、MZX、NXGX 分层处理，按原层级重新封装；MZX 的 literal 写入不保证原压缩率。
- **pfs-rs：** 使用 `create INPUT_DIR/ --no-smart-detect -o OUTPUT.pfs`，显式保留内容根目录语义，避免外层目录或智能检测改变资源路径。
- **CriCodecs：** CPK 少量替换优先读取原包列表，按完整 `path` 找到十进制条目索引，再用 `INPUT.cpk --replace "INDEX=LOCAL_FILE" -o OUTPUT.cpk`；不要把路径直接用作替换目标。目录重建使用 `--build -f cpk INPUT_DIR -o OUTPUT.cpk`，按原包证据指定 profile、对齐与压缩，不能声称自动保留全部 ID/布局。音频编码使用 `--encode -f hca|adx|ahx INPUT.wav -o OUTPUT`（三种格式择一），参数及密钥按对应文档确认。所有输出使用新路径；完成后重新列出并原样提取，核对路径、条目身份、资源哈希和音频元数据。
- **GARbro：** 使用 `c` 或 `pack`，显式提供 `-t` 与 `-o`，并将输入目录放在最后。需要包含嵌套资源且写入器支持时，使用 `-R`。用重复的 `-O Name=Value` 参数提供必要格式选项。写入器无法保留所需路径时，不要将嵌套输入扁平化。

以下是确认设置与暂存内容后重建 XP3 的 PowerShell 示例。变量必须包含已解析的路径；其中的压缩设置只是示例，并非对原始归档属性的推断：

```powershell
& $garbro i -q $originalArchive
& $garbro f --writable -q
& $garbro options XP3 -q
& $garbro c -t XP3 -o $outputArchive -R -O RetainDirs=true -O CompressIndex=true -O CompressContents=false -q $stagingDirectory
```

继续之前检查每个进程的退出码。失败时保留有用诊断并修正原因；不要猜测密钥或更换格式反复重试。除非覆盖该输出已获授权，否则不要添加 GARbro 的 `-y` 或其他工具的覆盖参数。上述 GARbro 示例创建成功后将最终归档路径输出到 stdout；其他工具的输出规则以各自文档为准。

对于使用 GARbro 的暂存清单，优先使用 `resource_workflow.py pack`：它会验证暂存哈希，使用已记录的格式与选项创建新归档，将其提取到新的验证目录，并写入资源比对报告。不会覆盖已有归档、清单或工作目录。其 `verify` 同样仅调用 GARbro。其他 CLI 由 AI 助手记录完整命令、输出路径与逐条比对结果；MRG 等具有填充或索引命名的格式按原条目身份和格式规则验证，不按生成的提取文件名直接对齐。比对失败不能报告为重建完成。

## 验证与交付

- 重新打开输出归档并列出内容。将路径与文件数量同预期资源集比较，同时考虑文档说明的格式特定名称规范化行为。
- 将其提取到单独的验证目录，不进行音频或图片转换。比较提取文件与暂存资源的哈希：替换条目必须与预期替换字节一致，未修改资源必须保持不变。写入器有意执行的资源变换须明确说明。
- 对最终归档中的替换资源执行相应格式检查：脚本解析及引用、图像解码和属性、音频解码与元数据等。若 CLI 访问限制导致无法重新打开或提取，准确说明未能完成的检查；仅创建归档不代表重建已验证。
- 对最终归档原样提取后的替换资源，按其格式复核长度、偏移及目标加载器的读写边界；转换格式、重新封装或资源字节改变后重新验证。音频解码检查按前述专项要求执行。已知长度不一致或越界未修正前停止安装；无法执行引擎验证时单独标记未验证，不得以哈希比对通过或 `complete: true` 代替此项结果。
- 如果游戏运行验证属于用户请求范围且环境支持，检查有代表性的修改：脚本执行与跳转、图像显示、音频播放或其他资源加载；否则标记游戏内运行未测试。成功往返提取不能证明游戏兼容性。

交付输出归档的绝对路径、封包模式、格式与相关设置、替换及保留资源数量、验证结果，以及尚未解决的兼容性限制。说明是否进行了游戏内运行验证及其覆盖范围。
