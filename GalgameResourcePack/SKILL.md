# GalPack

将原样资源与确认的替换资源合并，创建新归档并重新提取比对。归档格式、音频格式和游戏加载行为分别验证。

## 开始与路线

1. 确定原始归档、原样资源根目录、替换资源、输出位置及完整重建或补丁模式。信息足够时直接继续；没有原始归档时需要明确目标格式和创建参数。
2. 按[工具索引](commands/index.md)选择随附 CLI，读取对应命令；程序路径相对于本技能根目录解析。可读格式不代表可写，默认选项不代表原始设置。
3. 读[归档重建流程](guides/packing.md)。使用 GalTTS 资源清单时再读[资源交接与重建](guides/resource-workflow.md)，按 `init → merge → pack/verify` 执行。

## 共同约束

- 默认输出到新路径，保留原始归档与替换输入。安装到游戏目录遵循用户已有授权。
- 每个归档使用独立基线。完整重建保留所有未替换条目，按完整相对路径匹配，不扁平化、猜名或静默增删。补丁模式须有目标游戏加载规则的证据。
- 基线是未转换的资源字节；映射、清单、暂存产物和验证目录分别存放。TTS 的 `asset_root` 必须与基线根目录一致。
- `resource_workflow.py init/merge` 使用标准库；`pack/verify` 仅支持 GARbro。其他 CLI 按命令文档独立执行创建、重新提取和资源比对，不能传给 `--garbro`。
- 创建参数须能表达当前格式版本、目录、压缩和加密要求。无法表达时报告具体限制，不生成默认替代品冒充兼容结果。保留工具运行依赖及许可证。
- 音频编码、采样率、声道、循环与封装长度按目标格式验证；改扩展名不是转码。条目索引、CPK ID、AWB wave ID 和脚本引用分别核对。

## 验证与交付

创建后重新列出并原样提取新归档，比较预期路径、数量和哈希；替换条目必须匹配替换字节，未修改资源保持不变。有意的格式变换须单独说明并验证。

按[资源交接指南](guides/resource-workflow.md#解码长度与越界预防)检查实际封装长度、目标解码器分配与输出边界；最终归档提取后的字节再次复核。生成审计通过、哈希一致和游戏播放是不同结论；已知长度错误或越界未修复前停止安装。无法执行目标引擎检查时单独标记未验证。

交付归档绝对路径、模式、格式与创建参数、替换与保留数量，以及资源往返、引擎边界、游戏播放各项状态。比对失败不能报告重建已验证；未知格式或加载问题可交给已安装的 GalReverse 分析，不依赖其存在才能完成已知格式任务。

## 引擎经验闭环

识别引擎后，按[经验积累流程](guides/engine-learning.md)查询用户本地库和[随包经验索引](catalog/experiences.json)，核对版本、方言和失效条件。每完成一次本阶段的真实验证，自动保存成功报告；有可分发的通用方法时收录为引擎资料。合成验证只能记录为合成等级，失败或未知结果不能写成成功经验。经验不改变任务范围与授权，用户指定仅本地保存时不修改技能资料。
