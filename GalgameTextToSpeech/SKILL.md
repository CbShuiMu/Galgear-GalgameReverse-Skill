# GalTTS

使用用户选择的 TTS 后端，根据中文对白与原始参考音频生成替换语音。保留源资源和输入映射，不负责翻译。

## 开始与路线

1. 读[输入与命令](guides/inputs-and-commands.md)，用 `scripts/galtts.py memory --where` 和 `memory` 定位并读取用户状态。首次配置只询问请求和已有配置中无法确定的后端、输入、资源根目录与输出位置；不预选模型、硬件或个人路径。
2. 读[映射到任务契约](contracts/dialogue-mapping.md)，确认共享语音和多段对白的生成语义。旧单音频映射继续可用；多音频必须显式分段。
3. 按[后端适配器](guides/backends.md)复用或注册所选环境，使用其 Python 解释器运行 `plan`。检查文本、路径、唯一任务数、引用数、格式支持和已有输出冲突。
4. 在用户授权范围内生成样本或完整批次。完整结束后运行 `handoff` 或 `audit`，交付实际输出路径和审计结果。

## 共同约束

- 新项目使用 `relative` 输出布局，保留相对于 `asset_root` 的目录与文件名；没有布局设置的旧项目保持 `flat` 行为，迁移使用新输出目录。
- 同一资源的相同文本只生成一次，计划和资源清单保留全部对白引用；相同资源对应不同文本时明确失败。多个音频不能自动重复整句，按 `audio_segments` 的实际文本生成。
- 保留受支持的容器、编码、采样率、声道和可确认位深；不支持时报告具体文件，不能静默更换格式。非语言音频按已确认的项目策略复制或报错。
- 通常每批复用一个模型实例；仅在源字节、文本、模型与参数指纹及输出哈希一致时续用结果。保护未验证的已有输出。停止标记在当前任务完成后生效，不自行恢复已停止任务。
- `memory`、`profile`、`configure`、`status` 和 `stop` 不加载模型。用户状态、机器路径和历史保存在技能包外；`memory.example.json` 只是空结构示例。安装、下载和外部服务遵循用户已有授权。

## 验证与交接

生成审计通过后才生成 `complete: true` 的 `.galtts/resources.json`。交付唯一资源数、语音引用数、共享复用数、失败数、原样保留的非语言资源数及绝对路径；样本完成不等于整批完成。试听或专项检查用于评价发音、漏读、情感和音色，生成审计不能证明音质。

面向归档重建时，`asset_root` 对应一个归档的原样资源根目录。按[游戏解码与越界验证](guides/inputs-and-commands.md#游戏解码与越界验证)分别检查封装长度、目标引擎解码口径与真实容量，并在最终归档解包后复核。不能复制旧长度、照抄 FFmpeg 的 PCM 大小或跨游戏套用修复公式；已知长度错误或越界未修复前停止安装，环境不可用时标记未验证。

批处理入口是 `scripts/galtts.py`，输入规范化是 `scripts/dialogue_mapping.py`，音频导出是 `scripts/audio_formats.py`；后端通过可选 IndexTTS、通用命令客户端或用户适配器接入。批处理依赖见 `scripts/requirements.txt`，模型依赖保留在各自环境中。
