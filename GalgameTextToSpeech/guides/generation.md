# 语音生成与交接流程

## 配置与预检查

按[批处理命令](../commands/galtts.md)用 `memory --where` 和 `memory` 读取用户状态。全新安装返回空配置，不预选模型或项目。复用已有选择；缺项按当前请求补齐，再按[后端适配器](backends.md)注册模型配置并配置项目。只安装所选模型环境缺少的批处理依赖，避免升级模型固定版本的依赖。

输入按[映射到任务契约](../contracts/dialogue-mapping.md)检查。使用所选模型环境的 Python 运行 `plan`，核对中文文本、实际资源路径、唯一任务数、引用数、格式支持和输出冲突。计划只覆盖当前映射，不把未映射资源静默加入批次。

新项目使用 `relative` 输出布局，保留相对于 `asset_root` 的目录、文件名及大小写；不同目录的同名资源分别输出。没有布局设置的旧项目保持 `flat` 行为，按基本文件名输出并拒绝重名。迁移时配置 `relative` 并使用新输出目录，不移动或覆盖旧结果。两种布局都会在交接清单中导出原始资源路径。

空文本或纯标点文本按已确认的项目策略复制原音频或报错；`copy` 保留的非语言声音不能计作中文合成。未经本工具验证的已有同名输出会阻止执行，应使用新输出目录，或在明确授权后迁移或替换。

## 生成、停止与续跑

为新模型、角色或设置生成样本并试听，检查发音、漏读、情感和音色；有帮助时比较 ASR 转录。`run --limit N` 产生 `sample_completed`，不代表整批完成。用户明确要求完整批次时，直接按请求执行，不额外增加样本审批步骤。

通常每批复用一个模型实例。默认每个条目最多重试两次；源音频、对白、模型配置、生成参数或适配器变化会使旧结果失效。续跑只跳过指纹和文件哈希均匹配的成功结果。停止标记在当前条目完成后生效；用户要求停止后保留结果，只有用户新近要求开始或恢复该批次时才使用 `--resume`。

Windows 长任务使用 PowerShell `Start-Process -WindowStyle Hidden`，将 stdout 和 stderr 重定向到任务日志；其他系统使用适合该主机的后台任务机制。报告真实 PID、输出目录和进度。只有用户要求时才配置自动重启或提醒。

输出目录的 `.galtts/` 保存预检查结果、计划、源 JSON 快照、`manifest.jsonl`、`progress.json`、中间 WAV、日志、`audit.json` 和 `resources.json`。源 JSON 和资源保持不变。

## 保留源格式的含义

检查实际音频流，识别容器、编码、采样率和声道数，并保留能够确定的 PCM/FLAC 位深。显式导出规则覆盖 WAV、FLAC、MP3、OGG/Vorbis、OGG/Opus、M4A/AAC、M4A/ALAC 和 AIFF 等常见组合。以预检查结果为准。如果缺少编码器、容器不受支持、文件损坏或扩展名与容器不符，不要仅修改扩展名后继续。

模型先输出 PCM WAV，再进行一次目标格式编码。无损中间 WAV 不会增加一次有损压缩。Vorbis 默认 q=5，可通过项目的 `vorbis_quality` 配置。有损格式重新编码无法保证相同码率、文件大小、元数据或编码器配置。上采样或增加声道数无法创造缺失的音频细节；多声道输出通常由单声道 TTS 上混，不能重建原始空间声场。

## 游戏解码与越界验证

替换语音需要重新封装或装入游戏时，在封包前验证以下项目，并对最终归档原样提取后的资源重复检查。普通播放器或 FFmpeg 能播放、归档往返哈希一致，都不能证明目标引擎解码时不会越界。

- **确定目标规则。** 从原始资源和目标游戏的引擎版本、实际解码器确定长度字段的含义、单位和缓冲区分配方式。区分压缩字节数、每声道采样帧数、交错 PCM 字节数及容器头尾开销；不要跨引擎套用某个格式的偏移或公式。
- **逐条检查资源。** 核对声明的压缩/解压长度、数据块与偏移边界、采样率、声道、位深、块对齐，以及格式提供的校验信息。检查字段可表示范围和整数溢出，拒绝截断、损坏或长度不一致的结果。不能复制旧语音长度，或用时长、码率估算替换后的长度。
- **核对真实解码输出。** FFmpeg 与游戏解码器可能对编码延迟、首尾裁剪、填充和块边界采用不同处理，得到不同的 PCM 数据量；这不表示压缩音频文件本身被改写。对影响缓冲区分配的字段，按目标引擎自身或与其匹配的解码器口径测量输出字节数、核对写入边界，再确定应写入的长度；不能直接照抄 FFmpeg 的 PCM 输出大小。格式元数据可用于预检查，但采样数等元数据到字节数的换算也须经过目标引擎验证。
- **验证内存边界。** 在隔离进程中采用保护页、哨兵或可用的内存检测工具，按引擎真实容量检查越界读写，尤其覆盖短音频、长音频、编码块边界和原样保留的非语言音频，并以原始语音作对照。设置超时；崩溃、异常退出、超时、哨兵被改写或缺少完整结果都判为失败。不要用统一增加固定字节数的方式掩盖未知差异，也不要跨可执行文件复用硬编码函数地址。
- **记录验证范围。** 在项目交付报告中记录资源 SHA-256、引擎/解码器版本或可执行文件 SHA-256、检查方法、覆盖数量、声明与实测长度、失败项和最终归档复核结果。资源或解码器改变后重新验证。无法运行目标解码器时，分别报告结构检查结果和“引擎解码边界未验证”；不得写成“越界检查通过”或“游戏内播放已验证”。已知越界未修正前停止安装。

这些是按游戏执行的验证要求，现有 `plan`、`audit`、`handoff` 不会自动执行引擎级内存检查。`.galtts/resources.json` 的 `complete: true` 表示当前生成批次审计完整，不表示游戏兼容性或内存安全已经验证；将引擎验证证据单独记入项目报告。

向封包阶段交接时，附上已测资源的哈希、解码器身份、测量口径、声明与实测长度，以及边界验证状态。若 Pack 又进行了转码或重新封装，应对实际封装资源重新测量和记录哈希，并更新受影响的暂存与验证清单；不能将 TTS 输出的旧验证结论直接用于变化后的字节。长度字段错误应按格式修正，不能通过随意裁剪音频或统一增加 256 字节来凑数。

## 审计与交接

完整批次结束后运行 `handoff`，更改配置后或封包前重新运行。它不加载模型，审计全部当前映射并导出 `.galtts/resources.json`；只有生成审计通过才设置 `complete: true`。`audit` 同样检查整个映射，样本与审计失败的结果不能作为完整替换集。

生成清单使用 `kind: gal-resource-manifest`、`schema_version: 1`、`stage: generated`，记录映射 JSON 哈希及原始和输出根目录。每个条目记录原始相对 `path`、原文件及生成文件的路径、哈希和大小、操作、指纹及全部对白引用。直接交接给 GalPack 时，用一个归档的原样资源根目录作为 `asset_root`，不同归档分别处理。

报告实际输出路径、唯一资源数、语音引用数、共享复用数、失败数、原样保留的非语言资源数，以及生成审计、试听和引擎边界各自的结果。只有已执行的检查才能报告通过。
